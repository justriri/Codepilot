How it works

From task to verdict in four stages

Each run is isolated in E2B, verified in a browser, and returned as structured JSON.

Submit→ Verify→ Capture→ Verdict
Stage 1

Submit task

Send a task from the console or API. Each run gets an isolated E2B sandbox.

Stage 2

Run verification

Dependencies install, your app starts, and Playwright verifies the live UI.

Stage 3

Capture evidence

Screenshots, recordings, and logs attach to the job as evidence.

Stage 4

Return verdict

A JSON report returns with status, test results, errors, and evidence links.

Developer API

Three calls to run verification

Create a session, subscribe to live pipeline events, then fetch the final JSON verdict. No polling required between stages.

api.codepilot.dev/v1
01 Create job
POST /api/sessions

Start a verification run. Returns a job ID and opens the event stream for that session.

POST /api/sessions
Content-Type: application/json

{
  "request": "Build a static site, start a server, verify the UI"
}

→ { "id": "job_…", "status": "queued" }
02 Stream progress
WS /api/sessions/{id}/stream

Watch each pipeline stage complete in real time: sandbox setup, browser checks, evidence capture.

WS /api/sessions/{id}/stream

← stage.started
← stage.completed
← evidence.captured
03 Fetch verdict
GET /api/sessions/{id}/verification

Retrieve the final structured report when the run completes. Gate merges and agent actions on the result.

GET /api/sessions/{id}/verification

→ {
    "status": "passed",
    "tests": […],
    "evidence": […],
    "next_action": "merge"
  }
